## 1. JiTu (逐笔成交)

### 数据结构
```json
{
  "JiTu": [{
    "stockcode": "002384",
    "value": "[{\"signal\":\"Tu\",\"time\":605},{\"signal\":\"Ji\",\"time\":608}]"
  }]
}
```

### 字段说明

| 字段 | 值 | 说明 |
|---|---|---|
| signal | `Tu` | 卖出 (Tu=退/卖) |
| signal | `Ji` | 买入 (Ji=积/买) |
| time | 605 | 时间 (毫秒，从 0 点起算 = 0:10:05.000) |

### ❌ 缺失字段

| 字段 | 状态 | 说明 |
|---|---|---|
| **成交量 (v)** | ❌ 不存在 | JiTu JSON 中只有 signal 和 time，无成交量 |
| **成交价 (p)** | ❌ 不存在 | JiTu 不含价格 |
| **成交金额 (a)** | ❌ 不存在 | JiTu 不含金额 |

**结论**: JiTu 只提供"方向+时间"，成交量和价格需要从其他格式获取。

## 2. tb1.0 (价格快照)

### 二进制结构

```
Header (40 bytes):
  [0:6]   = "tb1.0\x00"
  [6:10]  = count (DWORD) - 结构体数量
  [10:14] = reserved
  [14:18] = reserved
  [18:20] = struct_size (WORD)
  [20:22] = market (WORD) - 市场标识
  [22:26] = flags (DWORD)
  [26:30] = unknown1 (DWORD)
  [30:34] = timestamp1 (DWORD)
  [34:36] = unknown2 (WORD)
  [36:40] = timestamp2 (DWORD)

Data Area (变长):
  - UTF-16LE 编码的股票代码 (6位数字)
  - UTF-16LE 编码的价格字符串 (含小数点)
  - UTF-16LE 编码的成交量字符串
  - 4字节小端整数 (flags/volumes)
```

### 实际数据样本

#### 002384 (三安光电)
```
记录1: prices=[201.13, 4.5, 201.19]  volumes=[2384]    count=61
记录2: prices=[201.19, 7.67]         volumes=[]        count=41
记录3: prices=[201.13, 4.5, 201.19]  volumes=[2384]    count=61
```

#### 881270 (指数)
```
记录1: prices=[23864.2, 363.9, 1.5, 4.19]  volumes=[23500, 2405]  count=31
记录2: prices=[23864.2, 363.9, 1.5]        volumes=[23500, 2405]  count=31
```

### ⚠️ 待确认: prices 索引顺序

**问题**: prices 数组中哪个是最新价？哪个是买一/卖一？

**观察**:
- 002384: prices[0]≈prices[2]≈201 (接近)，prices[1]=4.5 或 7.67 (差异大)
- 881270: prices[0]=23864.2 (大数，可能是指数值)，prices[1]=363.9, prices[2]=1.5, prices[3]=4.19

**假设** (待验证):
- prices[0] = 最新价/收盘价
- prices[1] = 涨跌额 或 涨跌幅
- prices[2] = 某个参考价格

**需要**: 对照 THS 客户端实时行情确认每个 index 对应什么价格。

## 3. itb3.0 (十档盘口) — 最关键但未解析

### 帧结构

```
完整帧: 1258 bytes
  [0:40]   = 帧头 (Magic 0xFDFDFDFD + 元数据)
  [40:46]  = "itb3.0" 标记
  [46:86]  = itb3.0 header (40 bytes, 结构未知)
  [86:end] = 数据区 (1178 bytes)
```

### 数据区结构

```
发现: 0x24 ('$') 标记每 4 字节出现一次
  [0:4]   = 24 XX XX XX  (marker + 3字节数据)
  [4:8]   = 24 XX XX XX
  ...
  [64:68] = 24 XX XX XX
  
共 17 个 4 字节记录 (位置 0-64)
之后结构变化
```

### 尝试解码价格

| 记录 | 原始 hex | val24 | /100 | /1000 | /10000 |
|---|---|---|---|---|---|
| 0 | 24599604 | 300633 | 3006.33 | 300.633 | 30.0633 |
| 1 | 24561404 | 267350 | 2673.50 | 267.350 | 26.7350 |
| 2 | 24311004 | 266289 | 2662.89 | 266.289 | 26.6289 |
| 3 | 24089604 | 300552 | 3005.52 | 300.552 | 30.0552 |
| 4 | 24079604 | 300551 | 3005.51 | 300.551 | 30.0551 |
| 5 | 24039804 | 301059 | 3010.59 | 301.059 | 30.1059 |

**问题**: 这些数值无法对应 002384 (price~201) 或 881270 (price~23864)

**可能原因**:
1. 价格编码方式不是简单的除法
2. 这些帧对应的股票未知
3. 需要找到正确的 header 解析方式来确定股票

## 4. Redis 数据结构 (已确认)

| Key 模式 | 类型 | 用途 |
|---|---|---|
| `ths:l2:meta` | Hash | 连接元数据 |
| `ths:l2:pool` | Set | 订阅股票池 |
| `ths:l2:events` | Stream | 系统事件 |
| `ths:l2:tick:{code}` | Stream | 逐笔成交 (JiTu) |
| `ths:l2:quote:{code}` | Hash | 价格快照 (tb1.0) |
