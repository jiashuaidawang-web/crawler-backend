# 踩坑记录 2026-09-22

## 问题1：Docker 拉取镜像失败（EOF / 无法解析 Docker Hub）

### 现象
```
docker pull clickhouse/clickhouse-server:23.8
Error response from daemon: failed to resolve reference "docker.io/clickhouse/clickhouse-server:23.8":
failed to do request: Head "https://registry-1.docker.io/v2/...": EOF
```

### 根因（按影响排序）
1. **DNS 被污染**：`registry-1.docker.io` 解析到 Facebook IP `157.240.16.50`，而非真实 Docker Hub 地址
2. **Docker daemon.json 代理端口错误**：配置的是 `host.docker.internal:1080`，但 Clash 实际监听 `7890`
3. **Clash 不允许局域网连接**：`allow-lan: false`，导致 WSL2（Docker daemon 所在）无法访问 Windows 上的代理服务

### 修复
1. **DaoCloud 镜像加速器**（最终方案）：
   - 修改 `C:\Users\Administrator\.docker\daemon.json`：
   ```json
   {
     "registry-mirrors": ["https://docker.m.daocloud.io"],
     "log-driver": "json-file",
     "log-opts": { "max-file": "3", "max-size": "10m" }
   }
   ```
   - 重启 Docker Desktop 后拉取成功

2. **Clash 配置修复**（为后续联网需求）：
   - 修改 `C:\Users\Administrator\.config\clash/config.yaml`：`allow-lan: true`
   - 重启 Clash for Windows（路径：`D:\application\VPN\Clash\Clash for Windows.exe`）
   - 验证：`netstat -ano | grep 7890` 显示 `0.0.0.0:7890 LISTENING`

### 关键排查经验
- **DNS 污染检测**：`nslookup registry-1.docker.io` 返回非官方 IP 即可确认
- **Clash 监听范围**：`127.0.0.1:PORT` 仅本机可访问，`0.0.0.0:PORT` 局域网/WSL2 可访问
- **国内镜像可达性**：`docker.m.daocloud.io` 在当前网络下可用（其他如 163/百度/阿里云测试不可达）

## 问题2：ClickHouse 容器退出码 70（Broken Parts 超限）

### 现象
```
docker run ... clickhouse/clickhouse-server:23.8
# 容器不断重启，Status: Restarting (70)
```

### 排查过程
1. **第一层错误**（误判）：`Effective user of the process (root) does not match the owner of the data (clickhouse)`
   - 尝试修改数据目录权限、用 `--user 101:101` 启动 → 均失败
   - 实际这不是真正原因（数据卷权限本来就正确）

2. **真正根因**（从错误日志发现）：
   ```
   Code: 231. DB::Exception: Suspiciously many (499 parts, 0.00 B in total) broken parts
   to remove while maximum allowed broken parts count is 100.
   Cannot attach table `crawler`.`stock_weekly`
   ```
   - 之前 Docker 非正常停止（`docker system prune` 或 WSL 操作）导致 `stock_weekly` 表的 499 个数据 part 损坏
   - ClickHouse 默认限制 `max_suspicious_broken_parts=100`，超过则拒绝启动

### 修复
1. 构建自定义镜像 `clickhouse-fixed:23.8`：
   ```dockerfile
   FROM clickhouse/clickhouse-server:23.8
   COPY merge_tree_config.xml /etc/clickhouse-server/config.d/merge_tree_config.xml
   ```
2. 配置文件 `merge_tree_config.xml`：
   ```xml
   <?xml version="1.0"?>
   <clickhouse>
       <merge_tree>
           <max_suspicious_broken_parts>500</max_suspicious_broken_parts>
       </merge_tree>
   </clickhouse>
   ```
3. 启动命令：
   ```powershell
   docker run -d --name astock-clickhouse-win --restart unless-stopped `
     -e CLICKHOUSE_DB=wushi -e CLICKHOUSE_USER=default `
     -e CLICKHOUSE_PASSWORD=pamirs@123 -e TZ=Asia/Shanghai `
     -p 8123:8123 -p 9000:9000 `
     -v clickhouse_data:/var/lib/clickhouse `
     clickhouse-fixed:23.8
   ```

### 关键排查经验
- **ClickHouse 退出码 70** = EX_SOFTWARE，通常表示数据/配置问题
- **必须读错误日志**：`docker exec <container> cat /var/log/clickhouse-server/clickhouse-server.err.log`
- **容器不断重启时无法 exec**：用临时容器读卷数据 `docker run --rm -v <vol>:/data alpine ...`
- **broken parts 超限**是 Docker 非正常停止后的常见后果，提高 `max_suspicious_broken_parts` 即可恢复

## 问题3：Git Bash 路径转换导致 Docker 参数错误

### 现象
```
docker: Error response from daemon: OCI runtime create failed:
exec: "D:/Development/Tool/Git/Git/usr/bin/sh": stat ... no such file or directory
```

### 根因
Git Bash（MSYS2）会自动将 Unix 路径（如 `/usr/bin/sh`）转换为 Windows 路径

### 修复
- 方案1：双斜杠 `//usr//bin//sh`（部分场景有效）
- 方案2（推荐）：**用 PowerShell 脚本执行 Docker 命令**
  ```powershell
  docker run -d --name xxx ... image:tag  # 直接写单行，无转义问题
  ```

### 关键排查经验
- 涉及 Docker `--entrypoint`、`--user` 等非标准参数时，优先用 PowerShell
- 多行命令用 PowerShell 单行语法（空格分隔，不用 `\` 续行）
