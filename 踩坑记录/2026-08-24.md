# 2026-08-24 踩坑记录

## openGauss schema 相关问题

### 1. ON CONFLICT 语法不支持

**问题现象：**
```
syntax error at or near "CONFLICT"
```

**根因：** openGauss 不支持 PostgreSQL 的 `INSERT ... ON CONFLICT ... DO UPDATE` 语法。

**修复：** 用 `INSERT ... SELECT ... WHERE NOT EXISTS` 替代：
```sql
INSERT INTO job_definition (job_type, display_name, ...)
SELECT v.* FROM (VALUES (...), ...) AS v(...)
WHERE NOT EXISTS (
    SELECT 1 FROM job_definition jd WHERE jd.job_type = v.job_type
);
```

---

### 2. 表创建到了错误 schema

**问题现象：** 新表创建在 `dbuser` schema 而非 `public`。

**根因：** openGauss 默认 `search_path = "$user",public`，当前用户是 `dbuser`，所以未指定 schema 时表创建在 `dbuser` 下。

**修复：**
```sql
-- 方式1: ALTER TABLE 迁移 (无序列依赖时)
ALTER TABLE table_name SET SCHEMA public;

-- 方式2: 有 SERIAL/BIGSERIAL 序列依赖时，需重建
DROP TABLE dbuser.job_execution CASCADE;
CREATE TABLE public.job_execution (...);
```

**关键排查经验：** openGauss 中创建对象始终显式指定 `public.` 前缀，避免 schema 不一致。

---

### 3. to_regclass 函数不存在

**问题现象：**
```
function to_regclass(unknown) does not exist
```

**根因：** openGauss 不支持 `to_regclass()`。

**修复：** 用 `information_schema.tables` 或 `pg_tables` 替代：
```sql
SELECT EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name='xxx')
-- 或
SELECT EXISTS (SELECT 1 FROM pg_tables WHERE schemaname='public' AND tablename='xxx')
```

## 踩坑索引

| 坑 | 影响 | 修复状态 |
|---|---|---|
